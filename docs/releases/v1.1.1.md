# LocalBridge MCP `v1.1.1`

`v1.1.1` corrige un defecto que podía retirar capacidades ya autorizadas de un proyecto sin
que el usuario cambiara nada. No añade tools MCP, no modifica el protocolo `2026-07-28` y no
amplía permisos.

## El defecto

Al registrar un proyecto, LocalBridge recorre su carpeta para describir la estructura. Ese
recorrido tiene un presupuesto: si la carpeta contiene demasiadas entradas, el análisis queda
incompleto. Hasta ahora, un análisis incompleto marcaba el proyecto como pendiente de revisión
y eso bloqueaba la terminal.

La consecuencia es que **el crecimiento de datos dentro de la carpeta —una base de datos de
pruebas, una caché, un directorio de subidas— podía dejar sin terminal a un proyecto que ya
tenía Control total concedido**, en mitad de una sesión y sin ningún cambio de permisos.

## Qué cambia

- La cobertura del análisis pasa a ser información, no un estado de bloqueo. Un proyecto con
  estructura parcialmente analizada sigue operando con normalidad.
- El estado de un proyecto solo cambia por condiciones que requieren tu decisión: varias
  raíces sin resolver, carpeta ausente o definiciones en conflicto.
- El cliente MCP recibe el estado y la cobertura del análisis, de modo que puede explicar una
  estructura incompleta en vez de encontrarse un bloqueo sin causa visible.
- Todo cambio de estado de un proyecto queda registrado en la auditoría local.
- Consultar, leer y cerrar una terminal existente ya no se bloquean cuando el proyecto pasa a
  revisión; abrir una nueva o escribir en ella sí conservan esa comprobación.
- Un proyecto que quedó en revisión se reevalúa solo, incluso al iniciar la aplicación, así
  que una instalación afectada se recupera sin intervención manual.
- El recorrido respeta la lista de rutas denegadas, omite directorios de datos y cachés
  habituales y limita cuántas entradas consume una sola carpeta, de modo que una carpeta
  enorme ya no deja sin analizar al resto del proyecto.

## Compatibilidad

Los proyectos, permisos, aplicaciones, decisiones de confianza y el complemento MCP existentes
siguen siendo válidos. La cobertura del análisis se guarda en un archivo propio, así que una
versión anterior sigue leyendo la configuración sin error.
