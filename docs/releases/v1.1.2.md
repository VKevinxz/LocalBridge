# LocalBridge MCP `v1.1.2`

`v1.1.2` corrige la detección de campos de credenciales del navegador controlado. No añade
tools MCP, no modifica el protocolo `2026-07-28` y no amplía permisos.

## El defecto

Cuando el asistente rellena un formulario, LocalBridge rechaza los campos que parecen
credenciales: contraseñas, códigos de un solo uso o datos de tarjeta. Esa detección comparaba
fragmentos de texto en lugar de palabras completas, así que bloqueaba campos inocentes cuyo
nombre contenía por casualidad una palabra sensible. Un campo llamado `secretaria` se
bloqueaba por contener «secret», y uno llamado `wizard` por contener «card».

## Qué cambia

- La detección compara palabras completas, separando nombres escritos en una sola línea
  (`usuarioContrasena`), con guiones bajos o con números al final.
- Se reconocen términos en español que antes no se detectaban: `contraseña`, `clave de
  acceso`, `tarjeta`, `código de seguridad`, `secreto`.
- Se distingue «palabra clave» —un buscador— de una clave real.
- Se tiene en cuenta el texto de ayuda del campo, habitual en formularios en español donde
  el nombre interno es genérico.
- El tipo del campo y su marca de autocompletado siguen mandando sobre cualquier nombre: un
  campo de contraseña se rechaza siempre, se llame como se llame.

## Compatibilidad

No cambia permisos, proyectos ni configuración. Una sesión de navegador se comporta igual
salvo que ahora deja de interrumpirse en campos que nunca fueron sensibles.
